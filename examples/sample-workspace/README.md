# Sample workspace

A complete, fictional knowledge base. Sam Rivera, FitTrack, MealMate, Vantage
Labs, Bright Orchard, and Northwind Retail do not exist. Every address points at
`example.com` and resolves nowhere.

It exists so you can see the output before doing any work, and so every bug
report can be reproduced against the same data.

## Run it

```bash
export EKB_WORKSPACE=$PWD/examples/sample-workspace

scripts/ekb status
scripts/ekb index          # builds index/evidence-index.yaml from 8 records
scripts/ekb check          # cross-file consistency
scripts/ekb shortlist 2026-03-14-northwind-flutter-engineer --refresh
scripts/ekb validate 2026-03-14-northwind-flutter-engineer
scripts/ekb render 2026-03-14-northwind-flutter-engineer   # needs the pip deps
```

The render produces a one-page PDF and DOCX, and a validation report scoring
95/100 with two honest gaps.

## Read it in this order

**1. `projects/fittrack.yaml`** — what a curated record looks like.

Notice `fittrack-003`. It carries a real before/after measurement, and its
`limitations` field immediately narrows it: profile mode, one device, not a
cross-device claim. That limitation is what lets the number be used at all.

Notice the two analysis headers. The first records that history before 2024-09
is a squashed import, so per-commit attribution is unavailable there. The second
records a run that produced nothing and still advanced the baseline.

**2. `context/fittrack-questions.md`** — the conversation that produced it.

This is the most instructive file here. It shows an agent proposal being
confirmed, another being corrected, a high-risk `led` claim being asked about
individually, and a candidate being dropped because "migrated to null safety"
is real, routine, and would not survive a follow-up question.

It also shows `fittrack-candidate-003` arriving as "improved performance by 70
percent" and being corrected to the measured figure with its context, because a
percentage hides the fact that it is a profile-mode number on one device.

**3. `projects/mealmate.yaml`** — the weak evidence, recorded honestly.

`mealmate-003` is a prototype that was demonstrated internally and closed
unmerged. Its limitations say **not eligible for a resume claim, in any form**,
and `profile-constraint-003` enforces that. It stays in the knowledge base
because it is good interview material about scoping and about knowing when to
stop.

A knowledge base that only stores strong evidence is less useful than one that
stores the weak evidence honestly and records exactly why it can never be used.

**4. `profile/professional-profile.yaml`** — what holds across projects.

Two projects support two real strengths and one supporting one. Nothing rounds
the picture out. `profile-constraint-001` is an `unlock`: the rare constraint
that *permits* comparative language, for one specific claim, because a
measurement exists behind it.

**5. `applications/2026-03-14-northwind-flutter-engineer.screening.yaml`** — the
gate, before any evidence was read.

Note what it does not contain: no record IDs, no shortlist, no assessment of a
resume. It reads a posting, a profile, and a policy, and stops. Note also the
`not_assessed` entry: no domain exclusions are configured, so that check reports
that it could not run rather than silently passing.

**6. `applications/2026-03-14-northwind-flutter-engineer.evidence.yaml`** — the
selection decisions, written down.

This is where resume quality comes from. Every requirement lists its eligible
candidates with strength and signals, and every decision says why the winner
beat the runner-up. Two requirements have no candidates at all, and their
reasons say plainly that the experience does not exist.

**7. `artifacts/applications/.../resume.json`** — the model.

Every visible item carries a private `source_ref`. The first summary item uses
`source_refs` with two IDs, because "offline-capable shopping and tracking apps
shipped to both stores" is inherently a cross-project claim that no single
record supports.

## What the validation report says

```
Requirement coverage: 8 demonstrated, 1 stated, 2 unsupported
Selection score: 95/100
Warnings: single-page resume is underfilled at 69.7%
```

**The underfill warning is left in on purpose.** Two projects is genuinely not
enough content for a full page, and the correct response is more curated
evidence, never a longer summary or a padded skills list. Fixing it here by
padding would teach exactly the wrong lesson.

The `stated` requirement is "requirements work with product", carried by a
profile responsibility because that work leaves no Git trace and no project
record can demonstrate it. The two `unsupported` ones are real gaps, reported
plainly.

## What is not here

`resume.docx`, `resume.pdf`, and `validation.json` are gitignored. They are
regenerated by `ekb render` and by CI, and binary artifacts in a repository age
badly.
